## 📊 Структура обох форматів

### 🔷 СТРУКТУРОВАНИЙ ФОРМАТ

```
┌─────────────────────────────────────────────────────────┐
│                  name: "My Playbook"                    │
│                                                          │
│  vars:                                                   │
│    ├── global_var_1: value                             │
│    └── global_var_2: value                             │
│                                                          │
│  plays:                                                  │
│    │                                                     │
│    ├─ [0] Play 1                                        │
│    │   ├── hosts: all                                   │
│    │   ├── name: "Setup"                               │
│    │   ├── vars:                                        │
│    │   │   ├── play_var_1: value                       │
│    │   │   └── play_var_2: value                       │
│    │   └── tasks:                                       │
│    │       ├── [0] Task 1                              │
│    │       └── [1] Task 2                              │
│    │                                                     │
│    └─ [1] Play 2                                        │
│        ├── hosts: webservers                            │
│        ├── name: "Deploy"                              │
│        └── tasks: [...]                                 │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 🔶 ANSIBLE-СУМІСНИЙ ФОРМАТ

```
┌─────────────────────────────────────────────────────────┐
│           (Прямий список Play'ів - без wrapper)         │
│                                                          │
│  [0] - hosts: all                                       │
│        ├── name: "Setup"                               │
│        ├── vars:                                        │
│        │   ├── play_var_1: value                       │
│        │   └── play_var_2: value                       │
│        └── tasks:                                       │
│            ├── [0] Task 1                              │
│            └── [1] Task 2                              │
│                                                          │
│  [1] - hosts: webservers                               │
│        ├── name: "Deploy"                              │
│        ├── vars: [...]                                 │
│        └── tasks: [...]                                │
│                                                          │
│  [2] - hosts: cache                                     │
│        └── ... (третій play)                            │
│                                                          │
└─────────────────────────────────────────────────────────┘

Примітка: Ім'я плейбука генерується із першого play:
          "Setup (playbook)"
```

## 📏 Розмір та Складність

### Структурований формат - Контроль структури

```yaml
name: Project Build & Deploy          ← 1 рядок: назва плейбука
vars:                                 ← 1 рядок: глобальні vars
  image_registry: docker.io           ← Зберігаються на верхньому рівні
  build_cache: true
plays:                                ← 1 рядок: контейнер для plays
  - hosts: builders                   ← Play 1
    name: Build Images
    tasks: [...]

  - hosts: deployments                ← Play 2
    name: Deploy
    tasks: [...]
```

**Плюси:** Явна структура, легко читати, навіть з багатьма play'ів
**Мінуси:** Більше синтаксису для простих плейбуків

---

### Ansible-сумісний формат - Простота

```yaml
- hosts: builders                     ← Прямо Play 1
  name: Build Images
  tasks: [...]

- hosts: deployments                  ← Прямо Play 2
  name: Deploy
  tasks: [...]
```

**Плюси:** Мінімум синтаксису, як в Ansible, коротко
**Мінуси:** Глобальні vars важче вкладати

## 📋 Порівнення за кейсами

### 🟢 Кейс 1: Один простий play

```yaml
╔═══════════════════════════════════════════════════════╗
║              ANSIBLE-СУМІСНИЙ - КРАЩЕ                ║
╚═══════════════════════════════════════════════════════╝

- hosts: all
  name: Install Software
  tasks:
    - name: Update packages
      package:
        name: curl
        state: present

┌───────────────────────────────────────────────────────┐
│ Чому краще:                                           │
│ •短er syntax                                         │
│ • Читається як стандартний Ansible playbook         │
│ • Один play - без extra wrapper                       │
└───────────────────────────────────────────────────────┘
```

---

### 🟡 Кейс 2: Кілька play'ів з глобальними vars

```yaml
╔═══════════════════════════════════════════════════════╗
║            СТРУКТУРОВАНИЙ - КРАЩЕ                    ║
╚═══════════════════════════════════════════════════════╝

name: Production Deployment Pipeline
vars:                           # ← Глобальні vars ЯВНІ
  environment: production
  version: 2.1.0
  timeout_seconds: 300
plays:
  - hosts: databases
    name: Database Layer
    tasks: [...]

  - hosts: webservers
    name: Web Layer
    tasks: [...]

  - hosts: cache
    name: Cache Layer
    tasks: [...]

┌───────────────────────────────────────────────────────┐
│ Чому краще:                                           │
│ • Глобальні vars чітко видно на верхньому рівні     │
│ • Масштабується до 10+ play'ів                       │
│ • Легше читати в editor з розгортаннями              │
│ • Structure явно показує 3 層 архітектури             │
└───────────────────────────────────────────────────────┘
```

---

### 🔴 Кейс 3: Генеруємо YAML програмно

```python
# Python: генерування Playbook
from yaml import dump

# Структурований EASY:
playbook = {
    "name": "Generated Playbook",
    "vars": {"env": "prod"},
    "plays": [
        {
            "hosts": "all",
            "name": "Task Group",
            "tasks": [...]
        }
    ]
}
print(dump(playbook))  # Структура така як потрібна!

# Ansible-сумісний СКЛАДННІШЕ:
# Потрібно контролювати, щоб не додати name на верхній рівень
plays = [
    {"hosts": "all", "name": "Task Group", "tasks": [...]}
]
print(dump(plays))  # Просто список, потім генеруємо ім'я
```

```go
// Go: структурований SIMPLE
type Playbook struct {
    Name  string
    Vars  map[string]interface{}
    Plays []Play
}

pb := &Playbook{
    Name: "Generated",
    Plays: []Play{...}
}
// YAML marshaling: знаменно структурований!
```

### Що відбувається "під капотом"

```
┌─────────────────────────────────┐
│  1. Читаємо YAML файл           │
└────────────────┬────────────────┘
                 │
┌────────────────▼────────────────┐
│  2. Викликаємо UnmarshalYAML()  │
│     (custom функція)             │
└────────────────┬────────────────┘
                 │
      ┌──────────┴──────────┐
      │                     │
┌─────▼──────┐      ┌──────▼─────┐
│ Спробувати │      │   Якщо не   │
│ unmarsh як  │      │   спрацює,  │
│ []Play?    ├─NO──→│  спробувати │
│            │      │ структур.   │
└─────┬──────┘      └──────┬──────┘
      │ YES                 │
      │             ┌───────▼─────┐
      │             │ Fallback    │
      │             │ успішний?   │
      │             └───────┬─────┘
      │                     │
   ┌──┴─────────────────────┤
   │                        │
   ▼                        ▼
┌──────────────┐    ┌──────────────┐
│ Генеруємо    │    │ Беремо name  │
│ name:        │    │ з структури  │

│              │    │              │
│ plays = [X]  │    │ plays = [...]│
└───────┬──────┘    └───────┬──────┘
        │                   │
        └─────────┬─────────┘
                  │
        ┌─────────▼─────────┐
        │  Internal format  │
        │  {                │
        │   Name: string    │
```

## 📊 Таблиця еквівалентності

| Структурований | ↔️ | Ansible-сумісний | Результат |
|---|---|---|---|
| `name: "Playbook A"` | → | (генерується з Play 1) | `"Play 1 Name (playbook)"` |
| `vars: {x: 1}` | → | На рівні Play 1 | `plays[0].vars = {x: 1}` |
| `plays: [P1, P2]` | → | `[- hosts: ..., - hosts: ...]` | Обидва = 2 play'и |
| Кілька `name:` на верхньому | ✗ | Кілька `- hosts:` | Якщо, то помилка |

## 🚀 Performance

```
Обробка часу (приблизно):

┌─────────────────────────────────────┐
│ Ansible-сумісний: 5ms               │  ← Швидше на 0.5ms
│ (Один спробуй - успіх)              │     (часто вже готовий)
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ Структурований: 5.5ms               │  ← Трохи повільніше
│ (Один спробуй - fallback - успіх)   │     (спробуй + fallback)
└─────────────────────────────────────┘

⚠️  Різниця не суттєва для користувача (< 1ms)
✅  Обидва формати оптимізовані
```
