### 3. Виправлення проблем безпеки (ВИСОКИЙ ПРІОРИТЕТ)

#### Проблема 1: Вимкнена перевірка SSH host keys

**Поточний код:**

```go
HostKeyCallback: ssh.InsecureIgnoreHostKey(), // ❌ РИЗИК БЕЗПЕКИ
```

**Рішення:**

- Реалізувати HostKeyManager
- Використовувати known_hosts файл
- Додати опцію для строгої перевірки

#### Проблема 2: Відсутня підтримка скасування контексту

**Рішення:**

- Додати context.Context до всіх SSH операцій
- Реалізувати graceful shutdown
- Додати таймаути для всіх операцій

#### Проблема 3: Недостатня валідація команд

**Рішення:**

- Розширити CommandValidator
- Додати перевірку на shell injection
- Додати whitelist дозволених команд

### 2. Інтеграція з менеджерами секретів (ВИСОКА ЦІННІСТЬ)

**Навіщо:** Безпечне управління секретами

#### A. HashiCorp Vault

**Функції:**

- Читання секретів з Vault
- Динамічні credentials
- Автоматичне оновлення токенів
- Підтримка різних методів аутентифікації (Token, AppRole, Kubernetes)

**Приклад використання:**

```yaml
secrets:
  provider: vault
  config:
    address: https://vault.example.com
    auth_method: token
    token: ${VAULT_TOKEN}

vars:
  db_password: "{{ vault('secret/database/password') }}"
  api_key: "{{ vault('secret/api/key') }}"
```

#### B. Bitwarden

**Функції:**

- Читання секретів з Bitwarden Vault
- Підтримка організаційних колекцій
- Інтеграція з Bitwarden CLI
- Підтримка self-hosted Bitwarden (Vaultwarden)
- Кешування секретів з TTL

**Приклад використання:**

```yaml
secrets:
  provider: bitwarden
  config:
    server: https://vault.bitwarden.com  # або self-hosted
    email: admin@example.com
    organization_id: "org-uuid"
    session_timeout: 3600

vars:
  db_password: "{{ bitwarden('database-credentials', 'password') }}"
  ssh_key: "{{ bitwarden('ssh-keys', 'private_key') }}"
  api_token: "{{ bitwarden('api-tokens', 'github') }}"
```

**Архітектура інтеграції:**

```go
// internal/secrets/provider.go
type SecretProvider interface {
    GetSecret(path string, field string) (string, error)
    ListSecrets(path string) ([]string, error)
    Close() error
}

// internal/secrets/bitwarden/client.go
type BitwardenClient struct {
    cliPath    string
    session    string
    cache      *SecretCache
    orgID      string
}

func (bc *BitwardenClient) GetSecret(itemName, field string) (string, error) {
    // Check cache first
    if cached, ok := bc.cache.Get(itemName, field); ok {
        return cached, nil
    }

    // Execute: bw get item <name> --session <session>
    cmd := exec.Command(bc.cliPath, "get", "item", itemName,
                        "--session", bc.session)
    output, err := cmd.Output()
    if err != nil {
        return "", err
    }

    // Parse JSON and extract field
    var item BitwardenItem
    json.Unmarshal(output, &item)

    value := bc.extractField(item, field)
    bc.cache.Set(itemName, field, value)

    return value, nil
}
```

**Переваги Bitwarden:**

- ✅ Open-source та безкоштовний для особистого використання
- ✅ Можливість self-hosting (Vaultwarden)
- ✅ Простіший у налаштуванні ніж Vault
- ✅ Підтримка 2FA
- ✅ Кросплатформенність
- ✅ Зручний UI для управління секретами

    region: us-east-1

      instance-state-name: running

    kubeconfig: ~/.kube/config
    namespace: default
    selector: app=web

### 6. Підтримка rollback (СЕРЕДНЯ ЦІННІСТЬ)

**Навіщо:** Безпечне відкочування змін

**Функції:**

- Автоматичне створення snapshots
- Відкочування до попереднього стану
- Історія змін
- Selective rollback (окремі задачі)

**Приклад використання:**

```yaml
- name: "Deploy application"
  module: "copy"
  src: app.jar
  dest: /opt/app/app.jar
  backup: true

- name: "Rollback on failure"
  module: "rollback"
  when: "{{ deploy_result.failed }}"
```
